Privacy Policy

Effective date: October 21, 2026. Last updated: October 24, 2026. Published at https://veritasvpn.cloud/privacy.html. No-logs policy.

No-logs policy

  • We do not store browsing history, a log of the DNS names you look up, the contents of your VPN traffic, or your real connection IP. That address is not written to the account database, the connect log, or backups. A backup made by the previous script can still contain a WireGuard endpoint until that archive expires: 14 days on the server, and 60 days off site. It is not a connection history. See Retention.
  • When a peer is created, the log and the internal event store a short hash of the per-install device ID, the assigned tunnel IP, and the server endpoint. They do not store those values in the clear, and they do not store your real public IP.
  • The Stealth listener is started at error log level, on the VPN node and in the cluster, so a rejected connection does not record the stealth path. Error lines can still be written. This is not a browsing log.
  • We do keep an email address if you register with one. Email is optional. An anonymous Account ID has no email. We keep that Account ID, and we keep purchase history, for the life of the account.
  • Shield per-category block counts are optional. They are kept, with no domain names, for an account that uses Veritas Shield. A free account cannot connect, so those counts are not kept for it.
  • Crash logs and diagnostics are optional. They stay on the device unless you turn sharing on and send the report yourself, from your own email app. The report can include crash lines. We do not receive it unless you send that email. It does not include WireGuard keys or session tokens.

1. Who we are

Veritas Ark, in Asunción, Paraguay, operates VeritasVPN. Veritas Ark is the controller of the personal data described in this policy.

This policy covers the website, the Android app, the Linux app, the Chrome extension, and the VPN service at veritasvpn.cloud. VPN servers are in Paraguay. Windows and macOS apps are not offered.

Privacy requests go to contact@veritasvpn.cloud.

2. What we do not collect

We do not collect or store:

  • Browsing activity or browsing history
  • A log of the DNS names you look up
  • The contents of your VPN traffic
  • Your real connection IP, including in backups

The connection map in the Android and Linux apps shows only the server location in Paraguay. It does not use your device location.

Veritas Shield is a best-effort DNS filter for WireGuard clients that use the in-tunnel resolver. A free account cannot connect, so Shield does not filter that account. Premium connects with malware, phishing, scam, cryptomining, and tracker hostnames blocked. Ads and adult domains stay off until that Premium user turns them on. Blocking is a DNS NXDOMAIN response, not removal of ads or trackers inside a page. Prometheus keeps aggregate counts (requests, blocks by category, resolver errors, list freshness) for 21 days and does not record query names. Session block totals are keyed by the temporary WireGuard tunnel IP, expire after about 2 hours without a heartbeat, and are cleared when the peer is removed. Account totals by category, with no domain names, are kept for about 8 days. When Shield blocks a name, that name is held in gateway memory for up to about 10 minutes, so the same block is not announced again, and in a Redis cache for about 2 minutes, keyed by the tunnel IP, so the app can show a notice. That cache is not written to disk, is not your public IP, and is deleted when the peer is removed. It is not a query log: lookups that are allowed are not stored. Upstream DNS-over-HTTPS resolvers still see hostnames we forward for lookups that are not blocked.

3. Data we collect

Account

You can create an email account or an Account ID account that has no email. An Account ID account is not a claim that we hold no data about the service.

  • Email address, if you register with email
  • Password hash (bcrypt). We do not store the password itself
  • Account ID
  • SHA-256 hashes of refresh tokens, email-verification tokens, and password-reset tokens
  • Account creation time, email verification time, plan, and subscription status

Access tokens last 1 hour by default. Refresh-token hashes last 7 days by default. Verification links expire in 1 hour. Password-reset links expire in 20 minutes. Email accounts that are never verified are deleted after 72 hours. That cleanup runs every 6 hours.

Device and tunnel metadata

When a device connects we store, for that peer:

  • WireGuard public key and a preshared key used to operate the tunnel
  • Assigned tunnel IP, server, status, and create time
  • A random per-install device ID. The app creates it on the device. It is stored with the peer so one account can have one peer per install, up to the plan's device limit. It is not an IMEI, Android ID, advertising ID, or MAC address. Logs and internal events store a short hash of it, not the raw value
  • Device name, platform, model, OS version, and client version
  • Last handshake time
  • Veritas Shield toggles

Android sends the manufacturer and model as the device model. The Linux app may send the computer hostname as the device model. The name, model, and OS version are display data for your account. The per-install device ID is also how the service enforces the device limit. None of these is a hardware identifier such as an IMEI, Android ID, or MAC address.

Your real public IP may be read in memory to choose a LAN or WAN endpoint for that response. It is not written to the database, the connect log, or backups.

Short-lived IP checks

  • Authentication rate limits store the client IP in Redis only as part of a counter key. Those keys expire with the limit window. The longest window is 1 hour (account creation, verification resend, and password-reset hourly limits). Sign-in counters expire after 1 minute.
  • When a security check is required, we send the client IP to Cloudflare Turnstile with the challenge token. We do not keep that IP after the check.

Payments

  • Google Play app: Google Play Billing. Google processes the payment. We receive purchase and subscription status, not your full card details. The app sends Google a one-way hash of the Account ID so the purchase can be matched to the account. That hash is not the Account ID and cannot be used to sign in. Purchases started before this change may still be matched using the Account ID that was sent with them. Deleting the account does not cancel the Google Play subscription.
  • Website, Linux app, and the Android app installed from this website rather than Google Play: self-hosted BTCPay, paid in Bitcoin. There is no card checkout on this path. We store the amount, currency, plan, status, and timestamps against your account. The BTCPay invoice is tagged with your account ID.

A Bitcoin checkout that is still pending after 4 days is marked failed in purchase history and then kept for the life of the account.

Support and diagnostics

If you email contact@veritasvpn.cloud, we keep what you send, including the address you wrote from. If you open a GitHub issue, that issue is public and stored by GitHub.

Diagnostics are off unless you turn them on and send them yourself. A report can include app version, OS, device model, connection state, transport, handshake age, server address, and a sanitized last error. It is sent with your own email app. It does not include WireGuard keys or session tokens. We do not receive a report unless you send that email.

Website checks and the Chrome extension

  • The IP check on /check returns the request IP and coarse Cloudflare edge metadata for that page view. We do not build a profile from it. If coordinates are present, your browser loads OpenStreetMap tiles.
  • The DNS leak test resolves short-lived names through edns.ip-api.com. We do not operate that DNS authority and we do not store those query names.
  • The breach check sends the email you type to our edge function and then to XposedOrNot. We do not store that email.
  • After the Android app connects, it asks api.ipify.org, ifconfig.me, and icanhazip.com for the public address seen through the VPN. Those requests are bound to the VPN network. They are not sent on the network outside the tunnel, including in Stealth mode. We do not store the address they return. The app can show it as the VPN address.
  • The Linux app contacts api.ipify.org to test whether the tunnel has working public egress. It does not contact ifconfig.me or icanhazip.com. We do not store the address ipify returns.
  • The Chrome extension asks ipwho.is for an approximate location so its network map can draw a pin, and it can contact api.ipify.org. The result stays in the extension on your device. The extension proxies browser traffic; it does not log destination sites on our servers.

4. Purposes and lawful basis

  • Provide the account, VPN, and apps — performance of the contract (GDPR Art. 6(1)(b)).
  • Take payment and show subscription status — contract. Accounting records, where a law requires them, are a legal obligation (Art. 6(1)(c)).
  • Rate limits, Turnstile, and abuse prevention — legitimate interests in keeping the service available and resisting credential stuffing (Art. 6(1)(f)). The IP is not kept as a connection log.
  • Support email you send us — contract, or legitimate interests in answering you.
  • Diagnostics you choose to email — your action in sending the message. The in-app switch only prepares text; it does not upload it.
  • Legal process we are required to answer — legal obligation.

You can object to processing based on legitimate interests by emailing contact@veritasvpn.cloud. If we cannot provide the service without that processing, we will say so.

5. Processors and recipients

We do not sell personal data. We use these processors and recipients:

  • Cloudflare — website hosting (Pages), Tunnel in front of the origin, Turnstile, R2 backup storage, and DNS-over-HTTPS (cloudflare-dns.com) for names Veritas Shield forwards
  • Google — DNS-over-HTTPS (dns.google) as the other Shield upstream; Google Play Billing for the Play app, including a one-way hash of the Account ID on new purchases; a preconnect to fonts.gstatic.com on some download pages. That preconnect can send your IP address to Google. Those pages do not load a font stylesheet, and the marketing homepage does not preconnect
  • Resend — verification and password-reset email
  • The mailbox provider for contact@veritasvpn.cloud — messages you send us
  • BTCPay — self-hosted by us, for Bitcoin invoices on the website and Linux app
  • api.ipify.org — egress check from the Android app and the Linux app, and optionally the extension
  • ifconfig.me — egress check from the Android app
  • icanhazip.com — egress check from the Android app
  • ipwho.is — approximate location for the Chrome extension map
  • edns.ip-api.com — DNS leak test on the website
  • XposedOrNot — breach-check lookup
  • GitHub — only if you file a public issue
  • Telegram — operational alerts to us, such as a new account or a payment received. Those messages include the account type or the payment method. They do not include an email address, an Account ID, or an IP address

OpenStreetMap tiles load in your browser during the IP check map. We do not receive a copy of that tile request beyond what Cloudflare already sees as ordinary site traffic.

6. International transfers

The VPN servers and the account database are in Paraguay. Paraguay is not the subject of a European Commission adequacy decision. Using the VPN means your account and tunnel metadata are processed in Paraguay, because that is where the service runs.

The processors in section 5 can process data outside Paraguay, including outside the EEA and the United Kingdom. Cloudflare, Google, Resend, and the other recipients listed there operate in their own locations.

We have not appointed an EU or UK representative under Article 27.

7. Retention

  • Email, password hash, Account ID, plan — while the account exists
  • Refresh-token hashes — 7 days, or until you sign out or delete the account
  • Verification and reset token hashes — 1 hour and 20 minutes
  • Unverified email accounts — 72 hours
  • Active peers and device metadata — while the peer is pending or active. This includes the random per-install device ID
  • Removed peers — 30 days after removal, then deleted. This includes device metadata, keys, tunnel IP, and last handshake time
  • Payment rows in our database — for the life of the account, including failed Bitcoin attempts after they are marked failed at 4 days. Account deletion hard-deletes them
  • BTCPay invoices — kept on the self-hosted BTCPay server. Account deletion does not delete them
  • Redis IP rate-limit keys — at most 1 hour
  • Tunnel-IP block counters — about 2 hours, or until the peer is removed. These are totals, not names
  • Account category block counts — about 8 days in the Redis cache, with no domain names. Memory pressure can drop them sooner. Deleted when the account is deleted
  • Blocked names for a notice — gateway memory for up to about 10 minutes, and a Redis cache for about 2 minutes, keyed by the tunnel IP. Not written to disk. Deleted when the peer is removed. Not a query log and not your public IP
  • Prometheus — 21 days of aggregate metrics, without query names or your real IP
  • Cluster backups — an encrypted archive is kept for 14 days on the server. Encrypted copies in Cloudflare R2 are removed after 60 days. The archive includes the Veritas database and the BTCPay database. It does not include a peer endpoint or the address from a last handshake. A backup made by the previous script can still contain a WireGuard endpoint until that archive expires. It is not a log written when you connect
  • Other backup copies — the postgres backup script, where it is used, keeps 7 daily, 4 weekly, and 3 monthly copies (monthly copies are removed after about 93 days, about 3 months). Single-node recovery snapshots are removed after 35 days
  • Application container logs — connect logs do not include your real public IP. The peer-created log and internal event store a short hash of the per-install device ID, the assigned tunnel IP, and the server endpoint, not the raw values
  • Origin nginx and ingress access logs — disabled. They are not written to our disks. Cloudflare may still retain edge logs under Cloudflare’s own policies. We do not keep a separate access-log archive

A deleted account can remain inside a backup until that backup expires. We do not use backups to restore a deleted account into the live service except to recover from an incident, and a restored copy is not a reason to reopen the account.

8. Deletion

You can delete your account yourself. The public page https://veritasvpn.cloud/account explains this before you sign in.

  • On the web: sign in at https://veritasvpn.cloud/account, open Account, then Delete my account
  • In the Android app and the Linux app: Account, then Delete account, then confirm
  • In the Chrome extension: open Delete account, which links to the same account page
  • By email: write to contact@veritasvpn.cloud and include the Account ID. Account ID accounts have no email on file, so the message has to include that ID

Email accounts confirm with the password. Account ID accounts confirm with the Cloudflare security check. Deletion signs you out and clears the local session. In our live database we delete the account, sessions, peers, subscription row, and payment records.

We still keep:

  • Encrypted database backups until they expire. Cluster archives are removed after 14 days on the server, and encrypted copies in Cloudflare R2 are removed after 60 days. Where the postgres backup script is used, monthly copies are removed after about 93 days (about 3 months). Single-node recovery snapshots are removed after 35 days. See section 7. We do not restore a deleted account into the live service except to recover from an incident.
  • BTCPay invoices tagged with the Account ID, on the self-hosted BTCPay server, and a copy of the BTCPay database inside a cluster backup until that backup expires. The Google Play app does not use BTCPay.

Deleting the account does not cancel a Google Play subscription. Google can keep charging the Play account until you cancel in Google Play. Open Google Play subscription management. The Android app shows the same warning, and a button to that page, when the account has an active Play subscription. We do not cancel or revoke the Play subscription from our servers when the account is deleted.

9. Your rights

If the GDPR or UK GDPR applies, you can ask for access, rectification, erasure, restriction, and a portable copy of personal data we hold, and you can object to processing based on legitimate interests. You can withdraw a choice to email us diagnostics by simply not sending the report. Withdrawal does not affect an email you already sent.

Paraguay’s Ley 7593/2025 (published 27 November 2025) lists access, rectification, cancellation, and opposition rights. The law’s own timetable brings it into force about 27 November 2027. We will honor those rights when they apply. Ley 6534/2020 credit-reporting rules are largely superseded by Ley 7593 and are not how this VPN is operated.

California and Do Not Track

We do not sell personal information and we do not share it for cross-context behavioral advertising. We believe we are below the CCPA/CPRA business thresholds. You can still ask for access or deletion at contact@veritasvpn.cloud. We will not discriminate against you for asking.

We do not track you across other websites, so we do not change the service in response to a browser Do Not Track signal. Changes to this policy are posted as described in section 17.

10. Complaints

You can complain to a supervisory authority. If you are in the EEA, that is the authority in your country. If you are in the United Kingdom, that is the Information Commissioner’s Office. In Paraguay, once Ley 7593 is in force, the authority is the Agencia Nacional de Protección de Datos Personales under MITIC. Please contact us first so we can try to fix the problem.

11. Security

  • TLS for the website and API
  • WireGuard for the tunnel between your device and our server
  • bcrypt password hashes
  • SHA-256 hashes for refresh, verification, and reset tokens
  • Access limited to the operator and the systems that need the data
  • Encrypted backups: GPG when a recipient is configured for the postgres script, and AES-256-CBC with an HMAC sidecar for the cluster backup

No system is perfectly secure.

12. Breach notification

If we become aware of a personal-data breach that is likely to risk your rights, we will notify the competent authority without undue delay and, where the law requires it, within 72 hours. That includes Ley 7593 Article 17 when that law is in force, and GDPR Article 33 for people in the EEA or UK. If the breach is likely to result in a high risk to you, we will also tell you by email when we have one, or in the app.

13. Children

VeritasVPN is not for anyone under 16. Do not create an account if you are under 16. The apps do not ask for your age. If we learn that we have personal data of a child under 16, we delete the account and the data we control.

14. VPN-specific statements

  • We do not sell traffic or personal data
  • We do not monetize the contents of your traffic
  • We do not redirect traffic or inject content into it
  • Traffic is encrypted from your device to our server. The server decrypts it to forward it to the internet. We do not log the contents or the destinations

A diagnostics report, if you send one, contains app version, operating system, device model, connection state, transport, handshake age, server address, and a sanitized last error. It is created only when you ask, it is sent through your own email app, and it does not include keys.

15. Cookies

See the Cookie Policy. The site uses essential session storage, Cloudflare Turnstile cookies when a security check runs (including in the Android sign-in WebView, which allows third-party cookies for that check), and a preconnect to fonts.gstatic.com on some download pages. That preconnect can send your IP address to Google. Those pages do not load a font stylesheet. We do not use advertising cookies.

16. Law-enforcement requests

We review requests. We require valid legal process under Paraguayan law, or another process we are legally required to honor. We narrow the request to what the order covers. We tell the user when the law allows it.

If compelled, the live systems could produce an email address if the account has one, a password hash, session-token hashes, device and tunnel metadata, last handshake time, and payment records. BTCPay could produce invoices tagged with an account ID. We cannot produce browsing history, a DNS query log, traffic contents, or your real connection IP from the account database, the connect log, or a current backup. A backup made by the previous script can still contain a WireGuard endpoint until it expires, for the windows in section 7. A blocked name held so the app can show a notice may exist only for the short windows in section 7. Short-lived Redis rate-limit keys and a Turnstile check may exist only for those windows too. Our warrant canary states whether we have received a secret order we cannot describe.

17. Changes

We post changes on this page and change the Last updated date. That posted page is the notice. The apps do not show a separate acceptance screen for this policy, and a change does not send an automatic email.
