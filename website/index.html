DNS security

Threat protection in the tunnel

Android and Linux peers resolve through our private DNS gateway. Queries leave the server only over encrypted DNS. Known malware and phishing domains are blocked. We do not retain query names.

01Encrypted upstream

Private DNS gateway

WireGuard clients use our in-tunnel resolver. Lookups are forwarded over DNS-over-HTTPS to trusted public resolvers—not sent as plain DNS on the open internet from your device.

02Threat feeds

Malware & phishing blocks

Automatically refreshed security feeds (including URLhaus and Phishing Army) mark dangerous hostnames. Matched names resolve to NXDOMAIN so the connection never starts.

03No query logs

Aggregate metrics only

We keep counts such as total requests, blocks, and blocklist freshness—never domain names or account IDs. UI blocked counts are keyed by temporary tunnel IP (not your public WAN IP). Upstream DoH resolvers see hostnames we forward. Details are in the Privacy Policy.

WireGuard connections with private DNS threat protection, anonymous Account IDs, private Bitcoin payments, and public source under BSL 1.1. We do not advertise infrastructure or audits that do not exist.

We do not store browsing history, DNS query names, or destination traffic. We retain the limited account, billing, and WireGuard peer metadata needed to operate the service. DNS protection keeps aggregate and tunnel-IP blocked counts—not query names. Upstream DoH resolvers see hostnames we forward. See the Privacy Policy.

On Android and Linux, peers use our in-tunnel DNS gateway (always on while connected). Queries are forwarded over encrypted DNS (DNS-over-HTTPS) to trusted public resolvers, which see the hostnames we ask them to resolve. Hostnames on refreshed malware and phishing feeds are blocked with NXDOMAIN. Ordinary DNS, DNS-over-TLS, and well-known public DNS-over-HTTPS resolvers are blocked at the gateway so apps cannot easily bypass Protected DNS; uncommon or custom DoH endpoints remain a residual risk. Chrome’s proxy path does not use the same full-device DNS gateway. Blocked counts shown in the app are per tunnel IP for the current session baseline, not your public WAN IP. This is threat protection—not an ad or tracker blocker. While connected, you can safely probe blocking with https://dns-protection-test.veritasvpn.invalid. Before you connect, try our free DNS leak test.

The source is public under Business Source License 1.1. It is source-available rather than OSI open source, with competing commercial use restricted until the Change Date.

A kill switch blocks clear-network traffic if protection fails. Linux uses firewall and fail-closed routes while connected. On Android, enable Always-on VPN plus Block connections without VPN in system settings for the same leak protection—apps cannot force those toggles on. Chrome blocks browser traffic when its authenticated proxy fails. The current VPN egress is IPv4-only, so managed full-device clients route or block IPv6 while connected instead of allowing an IPv6 bypass. Chrome remains browser-only.
